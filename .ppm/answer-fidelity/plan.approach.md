## Design

1. **Path filtering belongs inside `resolve`, before the cap.** Filtering in a handler would make the `ok`/`ambiguous` verdict depend on presentation and would let the same query answer differently per tool. One signature: `resolve(source, query, { kinds?, path? })`, with `path` applied as `isUnderPrefix(node.file, path)` to every step's hits and to near misses.
2. **`resolve` owns the counts; handlers own the call.** The ambiguous variant gains `candidates_total` (pre-cap winners) and `candidates_shown` (returned), and every `why` is built from the same total. `next_call` is built by each handler because it is tool-shaped: `trace` echoes the caller's `direction`, `expand` does not.
3. **Bucket at read time, from rows the code already has, and keep the census in the payload.** `assemble()` already returns `unresolved: readonly UnresolvedRef[]` beside the coverage (`src/shared/domain/coverage.ts:65-69`), and `status` fetches the same rows, so each tool can call `bucketCensus(assembly.unresolved)` with no new query, no reader change and no schema change. The census goes in each tool's `payload.unresolved` (`{total, material, buckets}`) rather than into `Coverage`: adding required fields to `Coverage` would break five source literals and eight test literals, while `coverage.unresolved_edges` keeps its documented meaning and its role gating `total_relation: "eq"`. `total` and `unresolved_edges` are the same number from the same rows, so they cannot disagree.
4. **Material is a claim about possible user code, and it is computed from its own predicate.** `material = rows where evidenceKind === "ambiguous" OR bucket === "receiver_type_unknown"`. It is deliberately not "the buckets that sound risky": an unresolved relative import does hide user code, but until issue #12 lands every import failure is written as `evidence_kind: "dynamic"` (`src/indexer/resolve.ts:358`), so imports can only enter material through the ambiguous predicate today and will enter it automatically when #12 starts recording them as `ambiguous`. `dynamic_property_call` is non-material by construction: the extractor records a call as dynamic exactly when no declared target exists.
5. **Identity is recorded by the publisher, read through `GraphMeta`, exposed in `status.payload`.** Not in the envelope: `read_status` is per-answer freshness, and `DESIGN.md` §6 keeps repository identity in `status`. Branch comes from parsing `.git/HEAD` (reusing the freshness reader, so no child process at query time); the remote URL comes from `git config --get remote.origin.url` at publish time, where the worker already spawns git.
6. **`range` and `outline` extend `expand` without touching the reader.** `members(parentId)` already returns children in source order, so `outline` needs no query; `range` clamps to the node's own extent and rejects `from > to` with the existing refusal vocabulary.
7. **The runtime guard cannot catch a missing interpreter, and does not pretend to.** A missing `bun` makes `env` fail before any line of our code runs, so the guard covers the two cases it can observe — a non-Bun runtime and a Bun older than 1.4.4 — and the docs say so instead of implying a cure.
8. **`unresolved_edges` stays.** It gates `total_relation: "eq"` and is a documented payload key; the buckets and the material count are added beside it rather than replacing it.
9. **Change-set state is additive.** `ChangeSet` gains `entries: {state, path, from?}[]` beside the existing `changed`/`removed` arrays rather than replacing them, so no existing consumer breaks and the two tools can render `state`/`from` without a shared type flip. `--no-renames` goes, `R`/`C` parse into one entry carrying both paths, and a single unparseable record is skipped instead of nulling the whole parse.
10. **`Totals` widens to `number | null`.** #10 requires `test_gaps_total: null` for an empty change set, and an absent key would be a different contract ("unknown" rather than "not applicable"). The only readers are `?? fallback` expressions in `expand` and plain assignments in `trace`/`budget`, so the widening costs one file and no call-site logic. Every other total stays a number in practice.
11. **Import failure kinds are chosen by cause at write time.** `SymbolIndex` gains `moduleCandidates(module)` returning the sorted match set, with `moduleFile` expressed over it so the two cannot disagree; then a relative or `#` specifier with more than one candidate is recorded `ambiguous`, a `./`/`../` specifier with none is `missing_module`, and a bare/package/`node:`/`bun:` specifier keeps `dynamic`. The competing paths are appended to `evidence` after the specifier token, which is why the classifier reads the specifier only up to the first space — #12 can then add rows to `ambiguous` without moving any bucket.

## Phases

### phase_0: foundation contracts

Deliverable: the shared contracts every tool will consume — `resolve`'s path-and-counts signature, the pure unresolved classifier and its census, `meta` identity capture with a `GraphMeta` that reads it, the runtime guard as a tested pure function, and the write-time import taxonomy (#12) whose new evidence kinds feed #5's buckets. Sync barrier because phase 1 handlers cannot be written against a contract that does not compile, and every one of those handlers imports one of these modules. The envelope's `Coverage` is deliberately untouched in this plan, so no zero-coverage literal and no coverage fixture moves.

### phase_1: tool surfaces

Deliverable: `trace` (path filter, honest totals, `next_call`, bucket filter), `expand` (path filter and `next_call`, then `range` and `outline`), `status` (identity and bucket headline), `summary`/`impact` (material unresolved in totals), the empty-change-set driver and `test_gaps_total: null` (#10), and the change-set `state`/`from`/deleted rendering (#11) over the new `ChangeSet.entries`. Each task owns its own tool's manifest, handler and test, so they run concurrently; `expand`'s two tasks, and the three tasks that share `src/tools/summary/handler.ts`, are serialized by `pre_request`. Sync barrier because phase 2 documents payload shapes that must exist first.

### phase_2: documents and close

Deliverable: `TOOLS-SPEC.md` describing the new arguments and payload keys (including `state`/`from` and a nullable `test_gaps_total`), `DATABASE.md`/`DESIGN.md` describing the recorded identity, the coverage fields and the new unresolved evidence kinds, and the full definition-of-done run with the acceptance assertions. Sync barrier because it is the gate: nothing ships until it passes.
